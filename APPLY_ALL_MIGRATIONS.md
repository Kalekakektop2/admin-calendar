# Применение всех миграций для системы зарплаты

## 📋 Список миграций для применения

Для работы новой системы зарплаты необходимо применить следующие миграции в Supabase:

### 1. Таблица штрафов (если еще не применена)
- **Файл**: `supabase/migrations/004_fines.sql`
- Создает таблицу штрафов с RLS политиками

### 2. Таблица авансов
- **Файл**: `supabase/migrations/007_advances.sql`
- Создает таблицу авансов с RLS политиками

### 3. Поле encashment (инкассация)
- **Файл**: `supabase/migrations/005_encashment.sql`
- Добавляет поле инкассации в таблицу shifts

### 4. Поле advance (аванс)
- **Файл**: `supabase/migrations/008_advance_field.sql`
- Добавляет поле аванса в таблицу shifts

### 5. Поле meal_allowance (обед)
- **Файл**: `supabase/migrations/009_meal_allowance.sql`
- Добавляет поле обеда в таблицу shifts (по умолчанию 100₽)

## 🔧 Как применить миграции

### Через Supabase Dashboard:

1. Зайдите в ваш проект на [supabase.com](https://supabase.com)
2. Перейдите в **SQL Editor**
3. Примените миграции по порядку (004, 005, 007, 008, 009)
4. После каждой миграции нажимайте **Run**

### Через Supabase CLI (если установлен):

```bash
supabase db push
```

## ⚠️ Важно

- Применяйте миграции по порядку для избежания ошибок
- После применения миграций удалите старые смены: `DELETE FROM shifts;`
- Отключите триггер автоматического расчета премии (если еще не отключен)
- Проверьте, что все поля созданы корректно в таблице shifts

## ✅ Проверка после применения

После применения всех миграций убедитесь:

1. В таблице `shifts` есть поля: `encashment`, `advance`, `meal_allowance`
2. В таблице `fines` есть записи (или таблица существует)
3. В таблице `advances` создана
4. Форма закрытия смены работает с новыми полями
5. Расчет зарплаты работает корректно
