# AGENTS.md - Руководство для агентов

Этот файл содержит важную информацию о проекте "Админский календарь" для работы с Devin или другими AI-агентами.

## Проект

**Название**: Админский календарь  
**Тип**: Веб-приложение для внутренней отчетности компьютерного клуба  
**Стек**: Next.js 14 + TypeScript + Tailwind CSS + Supabase

## Команды разработки

### Запуск проекта
```bash
npm run dev
```

### Сборка
```bash
npm run build
```

### Линтинг
```bash
npm run lint
```

### Установка зависимостей
```bash
npm install
```

## Структура проекта

- `src/app/` - Next.js App Router страницы
- `src/app/admin/` - Интерфейс администратора (защищен middleware)
- `src/app/manager/` - Интерфейс руководителя (защищен middleware)
- `src/lib/supabase/` - Supabase клиенты (browser и server)
- `src/lib/auth.ts` - Функции авторизации и проверки ролей
- `src/types/database.ts` - TypeScript типы для Supabase
- `supabase/migrations/` - SQL миграции для базы данных

## Важные файлы

### Конфигурация
- `.env.local` - Переменные окружения (должен быть создан из `env.example`)
- `src/middleware.ts` - Защита маршрутов по ролям
- `src/lib/auth.ts` - Функции авторизации

### База данных
- `supabase/migrations/001_initial_schema.sql` - Основная схема
- `supabase/migrations/002_bonus_config.sql` - Конфигурация бонусов
- `supabase/migrations/003_bonus_calculation_function.sql` - Авто-расчет бонусов
- `supabase/storage_setup.sql` - Настройка Storage для фото

## Ключевые особенности

### Авторизация
- Используется Supabase Auth
- Две роли: `admin` и `manager`
- Middleware защищает маршруты `/admin` и `/manager`
- Функции в `src/lib/auth.ts` для проверки ролей

### База данных
- PostgreSQL через Supabase
- Row Level Security (RLS) включен
- Автоматический расчет бонусов через триггеры
- Storage для фотографий в bucket `shift-photos`

### RLS Политики
- Администраторы видят только свои смены
- Руководители видят все данные
- Фотографии доступны автору и руководителям

## Правила разработки

1. **Никогда не коммитить** `.env.local` или другие файлы с секретами
2. **Изменения в БД** должны быть через новые миграции
3. **RLS политики** должны быть обновлены при изменении структуры
4. **Типы TypeScript** в `database.ts` должны соответствовать схеме БД
5. **Авторизация** - всегда проверять роли в server components

## Supabase Setup

Если нужно настроить Supabase заново:

1. Создать проект на supabase.com
2. Применить миграции из `supabase/migrations/` по порядку
3. Применить `supabase/storage_setup.sql`
4. Создать `.env.local` с учетными данными
5. Создать тестовых пользователей через Auth + таблицу users

## Отладка

### Проверка соединения с Supabase
```bash
# Проверить переменные окружения
cat .env.local
```

### Проверка миграций
В Supabase Dashboard > SQL Editor проверить что таблицы созданы.

### Проверка RLS
```sql
-- Проверить включен ли RLS
SELECT tablename, rowsecurity 
FROM pg_tables 
WHERE schemaname = 'public';
```

### Проверка Storage
В Supabase Dashboard > Storage проверить что bucket `shift-photos` создан.
